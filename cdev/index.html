§Why it doesn't die
Six things a bare SSH shell can't do.
1
Survives anything

SSH disconnects, laptop sleep, a full reboot. tmux keeps the shell alive, systemd brings the box back to where it was.

cdev doctor
2
One identity per account

Every account gets its own home at ~/.claude-<account>. Name a session once and it always knows which one it belongs to.

cdev accounts
3
Reachable from anywhere

Open claude.ai/code or the mobile app, same account, same session, live — a green dot means it's actually there.

claude.ai/code
4
Comes back on its own

One registry file, one boot-time service. Every session you didn't kill is running again before you've finished your coffee.

cdev restore · auto
5
Tells you when it's gone quiet

Opt in with a webhook URL and a timer checks every five minutes. Silent until a session disappears without being told to.

cdev healthcheck · auto

§Commands(8)
cdev <subcommand> ... — bare cdev <name> creates and attaches.
1
cdev <name> [account] [dir]

Create a session if it doesn't exist yet, then attach to it. Account defaults to personal.

2
cdev status

List every running session with its account and uptime.

3
cdev kill <name>

Stop a session and drop it from the reboot registry.

4
cdev doctor

Check install health and point at the exact fix for anything broken.

5
cdev upgrade

Install the latest tagged release.

6
cdev restore

Recreate every registered session. Runs once at boot.

auto
7
cdev healthcheck

Report a session that vanished without cdev kill. Runs every 5 minutes.

auto
8
cdev uninstall

Remove cdev from this box. Running sessions are left alone.

!Known issues
Read this before you file a bug — it might already be documented.
!
Workspace not trusted, on first run

Claude Code's trust dialog is per-directory, not per-account, so a brand new project always needs it once. cdev detects the session dying and retries automatically — this usually isn't something you have to fix by hand.

!
Silent stalls on an expired login

A session that outlives its login just goes quiet — no error, no notification. If a session looks idle after a long time away, check whether it needs to log in again before assuming something broke.

!
A stale shell function can shadow the binary

An older, sourced-function install left loaded in a shell wins over the real one on the path. If a command ignores its own subcommand, run type cdev — if it says "is a function", unset -f cdev or open a new shell.
